# Установка обновления страниц магазинов

Пакет содержит только новые и изменённые файлы относительно `archive (3).tar.gz`. Пути внутри архива соответствуют корню сайта. Это патч исходников, а не полный дистрибутив Битрикс. Применять сначала на копии сайта с копией базы.

## Что изменено

Единый шаблон магазинов, контакты и изображения, три поля описания, выбор профильных товаров до 12 без повторов, бренды, акции, похожие магазины, фасеты магазина в разделах и корне, реальная пагинация, некликабельные крошки отключённых разделов, скрытие ссылок и кнопок отключённого продавца. Для магазина без товаров товарные блоки и якорь не выводятся.

Существующий путь `/shops/код.html` сохранён. Товары остаются на существующих адресах. Ядро `/bitrix/` не изменяется. Старый вложенный шаблон `news.detail/.default/template.php` остаётся в исходном проекте, но новая детальная страница его не вызывает.

## Порядок установки

1. Сохранить резервные копии базы и заменяемых файлов. Проверить отличия рабочей версии сайта от исходного архива: данный патч не включает изменения, сделанные после его создания.
2. Развернуть пакет на тестовом сайте с Битрикс и копией базы. Нужны PHP с mbstring, штатные классы Битрикс для инфоблоков и HTML-санитайзера. Очередь активности рассчитана на MySQL/MariaDB.
3. Из корня тестового сайта запустить CLI-команду `php local/tools/shop-page.php diagnose`. Это чтение данных; результат — JSON с типами свойств, найденными источниками данных, несопоставленными категориями и исключениями по длине Description.
4. Проверить `local/php_interface/include/shop-page/config.php`. Если `unmapped_categories` непустой, заполнить `category_sections` в формате `ID значения CATEGORY_FILTER => array(ID раздела, ...)`. Автоматическое сопоставление использует только уникальное совпадение названия раздела или XML_ID. Неоднозначные значения не угадываются. Проверить, что каждый заданный ID относится к каталогу 7.
5. Проверить источник собственных часов работы магазина (`hours_property`), свойство «Рекомендуем» (`recommend_property`), инфоблок акций (`sale_iblock`) и свойство связи акции с магазином (`sale_shop_property`). Диагностика показывает автоматический выбор: уникальное имя поля/инфоблока или единственную связь с инфоблоком магазинов. Если автоматического выбора нет, явно указать реальные коды/ID. Не подставлять часы центра вместо часов салона.
6. Выполнить `php local/tools/shop-page.php install`. Команда создаёт недостающие DESC_MAIN, DESC_ASSORT, DESC_HELP типа HTML с подсказками; включает MANUFACTURER в умном фильтре; создаёт три служебные таблицы и агент обработки очереди. Повторный запуск не создаёт дубли и не перезаписывает тексты. Несовместимый тип существующего поля вызывает ошибку. Команда не транзакционная: после исправления причины ошибки запустить её повторно.
7. Выполнить `php local/tools/shop-page.php reindex` либо штатную полную переиндексацию фасетного индекса каталога 7 в административной панели, если версия Битрикс не поддерживает используемый API. Команду запускают отдельно: большой каталог может потребовать времени.
8. Очистить компонентный и композитный кеш сайта, повторить diagnose и проверить сценарии ниже. Новая страница магазина рассчитывает состояние непосредственно из текущих данных без собственного межзапросного кеша. Штатные страницы товаров открываются без компонентного кеширования, чтобы состояние продавца не устаревало. На разделах каталога включён учёт фильтра в ключе кеша. При изменении магазина сбрасываются теги кеша магазинов и товаров.
9. После приёмки перенести те же файлы и настройки на рабочий сайт, выполнить install/reindex и очистить кеш. Отдельно проверить cron/агенты: очередь активности обрабатывается по 100 позиций за проход, а не внутри запроса сохранения магазина.

## Зависимость отключения товаров от редиректов

В поставляемом config.php оба флага `cascade_enabled` и `redirects_ready` равны false. Агент при этих значениях не меняет активность товаров. Не включать флаги до фактической проверки цепочек редиректов снятых товаров. Перенаправление только на тот же адрес со слешем недостаточно. Существующие редиректы исходного проекта сохранены, новый набор редиректов не создавался.

После подтверждения редиректов:

1. На тестовом магазине проверить нужные URL, выключить его и выполнить `php local/tools/shop-page.php dry-run ID_МАГАЗИНА` (после install). Команда показывает, сколько товаров будет отключено/восстановлено исходя из текущей активности магазина; сама данные не меняет.
2. Включить оба флага на тестовой копии, выполнить `php local/tools/shop-page.php enqueue ID_МАГАЗИНА`, затем запускать `php local/tools/shop-page.php work` до опустошения таблиц заданий. Проверить отключение и обратное включение. В обычной работе новые задания создаются при изменениях магазина и товара.
3. После приёмки повторить порядок на рабочем сайте. Уже отключённые до установки магазины автоматически массово не обрабатываются: их нужно явно поставить в очередь командой enqueue после проверки dry-run.

Журнал действий и ошибок — штатный журнал событий Битрикс, тип `KUBATURA_SHOP_ACTIVITY`. Таблицы `b_kubatura_shop_jobs`, `b_kubatura_shop_product_jobs` и `b_kubatura_shop_disabled` хранят задания и список отключённых механизмом товаров. Не удалять их до восстановления необходимых товаров. При сбое необработанные задания сохраняются; агент пишет ошибку и повторяет обработку при следующем запуске.

Принятый принцип восстановления: включаются только товары, которые отключил этот механизм. Товары, отключённые ранее вручную, не включаются. Явная ручная установка ACTIVE=N после отключения механизмом исключает товар из последующего восстановления. Для товара с несколькими продавцами достаточно одного активного связанного магазина, чтобы товар оставался активным. Эти уточнения исходного неоднозначного ТЗ нужно подтвердить при приёмке. Изменение активности выполняется очередью, поэтому проверять результат следует после её обработки.

## Принятые трактовки

- Три новых поля описания создаются по конкретному пункту 4.5, несмотря на общую фразу «новые поля не нужны».
- Пустой ANALOG_SHOPS запускает автоматический подбор. Пустая конечная выборка скрывает блок.
- Пока все три новых описания пусты, сохраняется старый DETAIL_TEXT. После заполнения хотя бы одного нового поля выводятся только новые описания. Старый текст в базе не удаляется. `legacy_description_fallback=false` отключает переходный режим.
- У товара учитываются активность, период активности и доступ текущего пользователя; неактивность раздела сама по себе товар не исключает.
- Остаток свободных мест среди 12 товаров распределяется по кругу в порядке категорий. Пустые группы пропускаются, повторы товара удаляются. Непрофильные товары не добавляются для количества.
- Если активные товары есть, но профиль не задан/не сопоставлен, блок 6 и якорь скрыты; сохраняются фактические бренды и ссылка на весь ассортимент в блоке 7. Несопоставленные категории следует исправить в конфигурации.
- Ссылка бренда ограничивает выборку одновременно магазином и брендом во всём каталоге: `/catalog/filter/shop-is-.../manufacturer-is-.../apply/`. Разделные ссылки с единственным manufacturer также поддержаны. Значение производителя поддерживается как список или строка; другие типы требуют адаптации по результатам diagnose.
- Для бренда-списка код — XML_ID, при отсутствии — текст значения с URL-кодированием. Исходный нативный умный фильтр нужно проверить после переиндексации на совпадение кодов. Дополнительные критерии нативного фильтра передаются прежнему компоненту с обязательным условием магазина/бренда, а не отбрасываются.
- Внешний контейнер логотипа 200×140 включает padding 12 px; изображение вписывается в оставшуюся область.
- Слишком длинный Title сначала теряет категорию, затем сокращается название с многоточием. Description длиннее 180 сначала теряет категорию, при необходимости сокращается. Короткий Description искусственно не дополняется: исключения короче 150 символов выводятся diagnose для согласования редактором.
- Пагинация списка магазинов рассчитывается динамически. Проверка выхода за границы в точке входа рассчитана на стандартный список с 20 элементами. Для дополнительных пользовательских фильтров списка отдельно проверить количество страниц после фильтрации.
- Обратный блок «Магазины этой категории» на страницах каталога не добавлялся: упоминание в макете не содержит отдельного согласованного требования DOCX.

## Проверки

Локально выполнены PHP lint изменённых PHP-файлов на PHP 8.3.33, проверка синтаксиса JS, 28 проверок чистых функций и 22 интеграционные проверки с подменой API Битрикс тестовыми данными. Проверены: телефон 8-800, регистр, метатеги, равномерный отбор, дубли и дефицит, пустые блоки, HTML-ссылки, 404 неизвестного магазина, 200/noindex пустого магазина, корневой фасет и пагинация. В headless Chrome проверены ширины 1440/768/375 px, отсутствие переполнения, один H1, 12 карточек и загрузка изображений; пустая страница проверена без JS.

Эти проверки не заменяют запуск на реальной базе Битрикс. В исходном архиве нет ядра и базы: миграции, фасетный индекс, события Битрикс, фактические соответствия категорий, обработка тысяч товаров, действия действующего кеша и ответы production URL локально не проверялись.

На тестовом сайте пройти весь раздел 7 DOCX. В частности:

- Плинтус Холл с несколькими категориями; квадратный/широкий логотип; несколько телефонов и пустой этаж.
- Магазин без товаров, без описаний/фото/брендов/акций; ручные и автоматические соседи.
- Действующая/будущая/истёкшая акция; изменение активного магазина и товара после прогрева кеша.
- Несуществующий магазин в фасете → HTTP 404; существующий без товаров → HTTP 200 и robots noindex, follow; непустой → только его товары и canonical на себя.
- `/catalog/filter/shop-is-plintus-kholl/apply/`, страницы 1/2 и номер за пределами.
- Активный товар в отключённом разделе, в том числе titebond-original-wood-glue: HTTP 200, отключённая крошка без ссылки, раздел не вернулся в меню.
- `/shops/?PAGEN_1=7` при исходных 114 активных магазинах → 404; при изменении количества проверять фактическую последнюю страницу.
- Выключение и восстановление тестового магазина, ранее выключенный товар, новый импорт и изменение SHOP, повторный запуск очереди и ошибка посреди обработки.

## Откат

Сначала вернуть оба флага активности в false и остановить агент `Kubatura\ShopPage\Lifecycle::agent();`. Если рабочие товары уже отключены механизмом, восстановить нужные магазины и дождаться восстановления товаров ДО удаления кода/таблиц; при аварии использовать согласованное восстановление из резервной копии базы. Затем вернуть заменённые файлы из резервной копии и убрать новые PHP/CSS/JS-файлы патча. Очистить компонентный и композитный кеш. Новые поля описания и их содержимое автоматически не удалять. Настройку MANUFACTURER и служебные таблицы откатывать только после сохранения данных и журнала, при необходимости повторить штатную переиндексацию.
